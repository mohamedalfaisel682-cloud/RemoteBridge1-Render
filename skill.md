# Master Skill: Professional Output Formatting, Bidi Protection & UI/UX Governance

## 1. Primary Output Language Rule (Arabic Communication Constraint)
- **Mandatory Response Language:** Always deliver and render all final responses, explanations, chat content, and contextual outputs in **pure, eloquent, clear, and grammatically/spelling-flawless Arabic**, even if the prompt or input message sent by the user is written in English.
- **Strict Arabic Linguistic Integrity & Proofreading:** Every Arabic response must undergo immediate internal proofreading before output to ensure:
  - **Zero Spelling & Typographical Errors:** Complete elimination of spelling mistakes, wrong character choices, or typos that cause reading confusion.
  - **Natural & Meaningful Phrasing:** Absolute prevention of literal machine-translations, awkward word unions, or unnatural Arabic structures that obscure the intended technical meaning.
  - **Contextual Clarity:** Concepts must be conveyed using precise, standard Arabic technical terms that make reading intuitive and effortless for the user.

## 2. Bidirectional Text (Bidi), Language Isolation & UI Overflow Prevention (English Technical Rule)
- **Bidi Isolation:** Isolate all English technical terms, variables, functions, and library names inside inline code backticks (e.g., `` `code` ``) or code blocks to prevent RTL/LTR rendering distortion.
- **Responsive UI & Text Fitting:** Prevent text clipping, overlapping, or hidden text using dynamic font scaling, proper text wrapping, or scrolling indicators.
- **Fit-to-Content Density (B16):** chat bubbles, tabs, table rows, cards, and buttons must hug their content — no oversized fixed heights or wasteful padding; density adapts to content, never the reverse.

## 3. Dynamic UI Iconography, Color Semantics & Contrast Optimization (English Technical Rule)
- **Icons & Animations:** Include static, dynamic, or animated icons reflecting exact functions. Active states feature motion/pulse.
- **Domain-Driven Color Palettes:** Choose color palettes and UI styling strictly matching the interface nature, app mission, and project goals.
- **Contrast, Transparency & Readability (Human Eye Optimization):**
  - **Dark Themes:** Deep black/charcoal backgrounds paired with high-legibility light text (white, bright yellow, light green) utilizing professional alpha/transparency (glassmorphism/blur).
  - **Light Themes:** Clean light backgrounds with dark high-contrast text (black/dark charcoal) with balanced opacity.
  - **Quick Preview:** Ensure designs provide instant, strain-free visual clarity for the human eye.
- **Visual Effects Matching:** Tailor effects, animations, and transitions precisely to the function, tab, option, and activity state.

## 4. Mandatory Response Structure (Arabic Visual & Ordering Rule)
Every response delivered to the user must conclude in the following precise order:
1. Main response, explanations, or code implementation (In Arabic).
2. **💡 الاقتراحات التطويرية الاستباقية (Top 5 Ranked Suggestions):** Up to 5 professional suggestions, ranked descending from most critical to least.
3. **📊 ملخص النتائج والتعديلات التنفيذية** (Executive summary of results - placed at the **very absolute end** of the response).

## 5. Comprehensive UI/UX & Design System Standards (معايير التصميم والتجربة البصرية الشاملة)
Applies to every visual deliverable generated by the assistant: reports, charts, icons, diagrams, illustrations, tables, interfaces, and output files (Markdown, HTML, Excel, Word, PDF, PNG, SVG).

### 5.1 Layout, Responsiveness & Spatial Design (التخطيط، التصميم المتجاوب، والفراغات)
- **Responsive by default:** Every deliverable must render correctly on mobile (320px+), tablet (768px+), and desktop (1200px+) without horizontal scrolling, clipping, or content overflow.
- Use a **12-column logical grid** or percentage-based widths; avoid fixed pixel widths that break on small screens.
- **White space / negative space:** minimum 16px–24px inner padding per section; 24px–40px spacing between major sections; avoid cramped layouts.
- **Visual hierarchy:** H1 (24–32px), H2 (20–24px), H3 (16–20px), body (14–16px), captions/notes (12px), with line height 1.5–1.7 for body text.
- Text alignment: **right-align** Arabic prose (ragged left, never justified); **left-align** code, URLs, numbers, and mixed-language tables.
- Never center long Arabic paragraphs; center only short headings, badges, or cards.

### 5.2 Typography & Human-Eye Readability (الخطوط وقراءة العين البشرية)
- Font stack: Arabic — `Segoe UI`, `Tahoma`, `Arial`; Latin/technical — `Inter`, `Roboto`, `Segoe UI`. Always include a legible Arabic fallback.
- Minimum body size: **14px** on screen, **11pt–12pt** for print/PDF/Word.
- All English technical terms, variables, function names, and library names must be isolated in inline code backticks `` `code` `` or code blocks to prevent RTL/LTR distortion.
- No text compression/stretching; letter-spacing normal to +0.03em for Arabic headings only.
- Body text must never be smaller than 12px in charts, tables, or captions.

### 5.3 Color Palette, Semantics & Contrast (النظام اللوني، الدلالة، والتباين)
- Project brand palette: **Deep Green `#14532d`** (primary), **Emerald `#16a34a`** (success/secondary), **Light Green `#dcfce7`** (cards/backgrounds), **Slate `#64748b`** (muted text), **Amber `#f59e0b`** (warnings/manual entry), **Red `#b91c1c`** (errors/critical), **Blue `#2563eb`** (links/interactive).
- **WCAG 2.2 AA minimum contrast:** 4.5:1 normal text, 3:1 large text/UI components. Verify programmatically; never estimate by eye.
- Semantic colors: green = success/safe, amber = caution/manual, red = error/prohibited, blue = link/action, slate = secondary info.
- **Link & path token (blue visibility):** hyperlinks and filesystem paths always render in blue — light `#2563eb` (≈ 5.3:1 on white, WCAG AA), dark `#60a5fa` on `#0f172a` — defined once as token `--link` and reused everywhere (chat, HTML, Word, Excel).
- **Never convey meaning by color alone:** always pair color with an icon, label, pattern, or text (e.g., red + ✖ + "خطأ").
- Dark theme variant (if produced): deep charcoal `#0f172a` background with high-legibility light text; avoid pure black.

### 5.4 Icons, Illustrations & Semantic Iconography (الأيقونات والرسومات التوضيحية)
- **Consistent style:** all outline, all filled, or all rounded — never mix styles within one report or interface.
- Minimum icon size: **24×24px** display; minimum touch target **44×44px** on mobile.
- Every functional icon must have an Arabic label or `aria-label`/`alt`; decorative icons must be marked hidden.
- Recognized symbols only: ⚠ warning, ✅ success, ❌ error, 📊 data, 🔗 link, 💰 price, 🔋 battery, 🛩 drone, 📡 signal, 🗺 map.
- Illustrations/diagrams must include Arabic captions below and alt text; never let an image carry the only copy of critical information.

### 5.5 Charts, Graphs & Data Visualization (الرسوم البيانية ومخططات البيانات)
- Chart text readability at 100% zoom: axis labels ≥12px, chart titles ≥14px, data labels ≥10px.
- Prefer bar/column/line charts over pie charts. Pie charts: maximum 5 slices; add direct labels or legend with percentages.
- **Colorblind-safe palettes:** avoid red-green-only distinctions; complement with patterns, hatching, or labels.
- Every chart requires: descriptive title, axis labels with units, legend (multi-series), and a source/note line.
- Maximum 6–8 data series per chart; group remainder into "أخرى / Other".
- Export: **SVG** for web/HTML, **PNG 150–200 DPI** for screen, **PNG 300 DPI** for print. Never upscale small raster images.
- Always include a **data table or CSV alternative** beneath every chart for accessibility and verification.

### 5.6 Output File Standards (معايير الملفات المخرجة)
- **HTML:** `lang="ar"`, `dir="rtl"`, UTF-8, viewport meta, `@media print`, semantic `<section>`, `<figure>`, `<figcaption>`, `<table>` with `<thead>`, external CSS block preferred over inline styles.
- **Excel (.xlsx):** one sheet per section, right-to-left sheet view, filled/bold/bordered header row, freeze panes at row 2, `SUM` formulas on totals, two empty manual columns for user cost entry («أقل تكلفة» then «أعلى تكلفة»), Arabic-labeled hyperlinks (e.g., "فتح الرابط"), auto-fitted column widths.
- **Word (.docx):** landscape for wide tables, RTL paragraph direction, Arabic font (Segoe UI/Tahoma), table grid style, properly sized embedded images (never stretched), captions below figures.
- **Markdown:** RTL-safe tables, image `alt` text in Arabic, no unescaped `|` inside cells, heading hierarchy never skipped (H1 → H2 → H3).
- **Images:** PNG for screenshots/photos, SVG for line art/icons/charts, WebP optional for web; descriptive Arabic `alt` text required.
- **Blue links & paths in every format:** HTML `a { color: #2563eb }` with filesystem paths wrapped in `<code class="path">` styled blue; Word links use the built-in Hyperlink character style (blue + underline); Excel hyperlinks use the built-in Hyperlink style (blue underlined); chat responses render URLs as blue links and wrap file paths in blue inline code.

### 5.7 Design QA Checklist Before Delivery (قائمة تدقيق التصميم قبل التسليم)
Before finalizing any visual deliverable, confirm:
- [ ] No overlapping or clipped text; no text outside containers.
- [ ] No icon smaller than 16px without an adjacent text label.
- [ ] No information conveyed by color alone.
- [ ] No chart text below 10px; all axes/legends labeled with units.
- [ ] No broken links; RTL text not mirrored or clipped.
- [ ] HTML prints correctly on A4 portrait/landscape.
- [ ] Word/Excel columns do not cut off at page boundaries.
- [ ] Chart text verified programmatically inside frame bounds (rule 5.8.4), not by eye.
- [ ] Illustrations/diagrams use `aspect="equal"` — no stretched proportions.
- [ ] Links and paths render blue (`#2563eb` light / `#60a5fa` dark) and remain distinguishable without color alone (underline or link semantics).
- [ ] File names use `snake_case`, descriptive Arabic/English, no spaces or special characters.

### 5.8 Visual Integrity & Layout Safety (سلامة إطار الرسم والنصوص والأيقونات)
Derived from the official *matplotlib constrained-layout guide*, *"Ten Simple Rules for Better Figures"* (PLOS Comput Biol), *Material Design iconography*, and WCAG 2.2. Purpose: eliminate text-smaller-than-frame and text-outside-frame defects.
- **Constrained layout everywhere:** every `matplotlib` figure uses `layout="constrained"`; save with `bbox_inches="tight", pad_inches=0.15–0.2`. Never trust default axes placement; never mix with `tight_layout()`.
- **Font-to-canvas ratio:** text scales with figure size — title ≥13pt, axis labels ≥11pt, ticks ≥10.5pt, data labels ≥10pt at final render size; bigger `figsize` ⇒ proportionally bigger fonts.
- **No-clipping contract:** threshold/limit labels go **inside** axes via blended transforms (`get_yaxis_transform()` / `transAxes`), never at data coordinates beyond the range; reserve label headroom with `set_ylim`/`margins()`.
- **Programmatic audit:** after `fig.canvas.draw()`, every text artist's `get_window_extent()` must lie inside the figure bbox — outside text fails the build; do not ship charts that print `OUTSIDE` warnings.
- **Aspect-ratio integrity:** data-coordinate illustrations call `ax.set_aspect("equal")` + `axis("off")`; `figsize` proportional to data extents — no stretching.
- **Don't trust defaults:** explicit `rcParams` block (font, brand colors, grid alpha ≤ 0.25, top/right spines off) on every chart script.
- **Color honesty:** brand palette or Okabe-Ito; no `jet`/rainbow; ≤6–8 series; bars start at 0; circles encode area not radius; no 3D; color never alone.
- **Chartjunk ban:** no decorative backgrounds; direct series labels over detached legends when feasible; ≤5 round y-ticks.
- **Caption mandatory:** every figure has an Arabic caption below with units, source, and ±15% margin notes.
- **Medium adaptation:** PNG ≥200 DPI (screen) / 300 DPI (print); SVG for web line art; check legibility at 100% zoom and 320px width.
- **Icon construction:** 24px grid, uniform ~2px stroke, 2–4px padding, optical centering, consistent corner radius, no sub-16px text inside icons, Arabic `aria-label`/`alt` always.
- **Legend placement:** outside legends via `bbox_to_anchor` are handled by constrained layout; never overlap data/titles; verify PNG and embedded HTML/Word.

### 5.9 Design Token System & Cross-Platform Universality (نظام الرموز التصميمية والشمولية)
Ensures cross-project consistency, instant dark/light theming, and clean developer handoff. Applies to every web/app deliverable:
- **Relative units everywhere:** typography and spacing in `rem`/`em`/`%`/`vw` — never hard-coded px in web outputs; layouts survive 50%–200% zoom and OS font scaling.
- **Overflow & box protection:** `box-sizing: border-box` on every layout box; embedded media (`img`, `video`, `svg`, charts) always `max-width: 100%; height: auto`; explicit `overflow: clip/auto` directives prevent text clipping or hidden content.
- **Spacing scale (8px grid):** 4 / 8 / 16 / 24 / 32 / 48px for margins, paddings, and gaps.
- **Color palette tokens:** primary/secondary/neutral/semantic with 50–950 shades (Material-style), WCAG AA contrast logged per pair — including the link token `--link: #2563eb` (dark theme `#60a5fa`).
- **Typographic scale:** modular 1.25x steps from display (largest) to caption (smallest), with line-height locked per size.
- **Icon & graphic constraints:** 24px base grid, vector paths (SVG) over raster pixels, ≥ 4px safe zones inside icon bounds, 1x/2x/3x asset exports.
- **Responsive breakpoints validated:** 375px (mobile), 768px (tablet), 1440px (desktop) — test at least two before delivery; log device-pixel-ratio assumptions (96 vs 144+ ppi) in export specs.
- **Compliance floor:** every visual output must adhere to at least 4 of the 5 core rule groups above (layout/responsiveness, typography, color/contrast, icons/media, tokens/breakpoints) to be considered professionally compliant.
